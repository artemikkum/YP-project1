# User Stories и критерии приёмки (состояние на конец спринта 5)

**Ситуация:** в колледже теряется информация об оборудовании компьютерных классов. Лаборанты ведут бумажные списки, администратор не знает, что и где неисправно, при проверке приходится обходить кабинеты вручную. Нужна простая программа, которая хранит все записи и позволяет быстро найти нужную.

Статус: ✅ реализовано, ⬜ запланировано.

| № | История | Критерии приёмки | Статус |
|---|---|---|---|
| US-1 | Как лаборант, я хочу видеть список всего оборудования, чтобы знать, что есть в классах | Пункт 1 выводит таблицу: номер, тип, наименование, кабинет, состояние; при пустой базе - «(записей нет)»; показывается число записей | ✅ спринт 1 |
| US-2 | Как лаборант, я хочу добавить новое оборудование, чтобы оно попало в учёт | Пункт 2 запрашивает поля; обязательные: номер, тип, наименование, кабинет, состояние; пустое поле - понятная ошибка; запись не создаётся при ошибке; пустой номер - автоматический INV-NNN | ✅ спринт 2 |
| US-3 | Как администратор, я хочу, чтобы номера не повторялись, чтобы каждое устройство было однозначно определено | Запись с существующим номером (в любом регистре) не создаётся, выводится «уже существует» | ✅ спринт 2 |
| US-4 | Как лаборант, я хочу находить компьютер по инвентарному номеру, чтобы быстро узнать, в каком кабинете он находится | Существующий номер - карточка; неизвестный - «Не найдено»; пустой ввод не приводит к аварии | ✅ спринт 3 |
| US-5 | Как преподаватель, я хочу видеть оборудование кабинета, чтобы понимать, чем можно пользоваться на занятии | Поиск по кабинету возвращает все устройства кабинета; нет совпадений - «Не найдено» | ✅ спринт 3 |
| US-6 | Как лаборант, я хочу менять состояние и кабинет записи, чтобы данные оставались актуальными | Enter оставляет поле без изменений; недопустимое состояние отклоняется, старые данные сохраняются; номер изменить нельзя | ✅ спринт 3 |
| US-7 | Как администратор, я хочу удалять записи с подтверждением, чтобы не потерять данные случайно | Перед удалением показывается карточка и запрашивается «да/нет»; «нет» - запись остаётся; неверный номер - «Не найдено» | ✅ спринт 3 |
| US-8 | Как администратор, я хочу фильтровать по состоянию («требует ремонта»), чтобы планировать ремонт | Фильтр по кабинету, по состоянию и по обоим сразу; неизвестное состояние - сообщение со списком допустимых | ✅ спринт 5 |
| US-9 | Как администратор, я хочу, чтобы данные не пропадали после закрытия программы, чтобы не вводить всё заново | Изменения пишутся в JSON сразу; после перезапуска записи на месте; нет файла - программа стартует с пустым списком | ✅ спринт 4 |
| US-10 | Как администратор, я хочу, чтобы повреждённый файл не приводил к тихой потере данных, чтобы данные не пропадали незаметно | При битом JSON выводится предупреждение, исходный файл сохраняется как *.broken-<дата>, программа не падает | ✅ спринт 4 |
