# Система учёта инвентаря компьютерных классов (спринт 4)

Консольное приложение на Python для учёта компьютерного оборудования колледжа.
**Проблема заказчика:** в колледже теряется информация об оборудовании - непонятно, где что стоит и в каком оно состоянии.

**Состояние на конец спринта 4:** данные хранятся в JSON-файле `data/inventory.json` и сохраняются между запусками. Фильтр - спринт 5.

## Где хранятся данные
В файле `data/inventory.json` (обычный текст, UTF-8). Файл можно копировать как резервную копию. Другой файл: `python main.py путь/к/файлу.json`.
- **Файла нет или он пустой** - программа стартует с пустым списком; файл создаётся при первом изменении.
- **Файл повреждён** - выводится предупреждение, исходный файл сохраняется рядом как `inventory.json.broken-<дата>`, программа стартует с пустым списком. Данные не теряются: исправьте копию вручную и верните имя `inventory.json`.
- Сохранение идёт после каждого изменения через временный файл (`.tmp` + замена), поэтому сбой не оставляет «полфайла».

## Docker (необязательно, не проверялось)
```bash
docker build -t inventory .
docker run -it --rm -v "$(pwd)/data:/app/data" inventory
```

## Требования
Python 3.11+ (pytest - только для запуска тестов, `pip install -r requirements.txt`).

## Запуск
```bash
python main.py
```

## Меню
| Пункт | Действие |
|---|---|
| 1 | Показать оборудование (таблица и число записей) |
| 2 | Добавить оборудование: номер (Enter - автоматически), тип, наименование, кабинет, состояние, дата и ответственный (необязательно) |
| 3 | Найти: по номеру (карточка), по кабинету или по названию/типу (таблица) |
| 4 | Изменить запись (Enter - оставить поле без изменений) |
| 5 | Удалить запись (с подтверждением «да/нет») |
| 0 | Выход |

Правила заполнения полей - `docs/DATA_RULES.md`.

## Тесты
```bash
python -m pytest
python -m unittest discover -s tests -t .
```
61 тест: логика, хранение (`test_storage.py`), меню и перезапуски (`test_cli.py`), демо-данные.

## Структура
```
main.py             меню и ввод/вывод
inventory.py        проверка данных, добавление, поиск, изменение, удаление
storage.py          чтение и запись JSON
data/inventory.json файл данных (при первом запуске - 12 демонстрационных записей)
tests/              автотесты
Dockerfile          образ для запуска (черновик)
USER_STORIES.md     требования
docs/               правила данных, тест-кейсы, дефекты
```

## Ограничения
- Нет фильтра по состоянию (спринт 5).
- Один JSON-файл, без блокировок: два одновременных запуска могут перезаписать изменения друг друга.
- Dockerfile не проверялся на машине подготовки (нет Docker).
