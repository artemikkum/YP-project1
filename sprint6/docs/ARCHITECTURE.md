# Архитектура

Три слоя, каждый в своём модуле:

```
main.py  (интерфейс: меню, ввод/вывод)
   │ вызывает
   ├──► inventory.py (логика: проверка, поиск, add/update/delete, фильтр)
   └──► storage.py   (JSON: load_items / save_items)
```

## Ключевые технические решения
1. **Запись = словарь.** Хранится в JSON без преобразований; обязательные поля проверяет `validate_item`.
2. **Логика отделена от ввода/вывода.** `inventory.py` не вызывает `input`/`print`, поэтому функции тестируются напрямую. Класс `App` получает функции ввода и вывода параметрами (`ask`, `say`); тесты подменяют их списком ответов - так проверяется всё меню без ручного ввода.
3. **Ошибки - исключениями.** `InventoryError` (с подклассами `NotFoundError`, `DuplicateError`) для ошибок данных, `StorageError` и `CorruptedStorageError` для файла. Меню перехватывает их и показывает сообщение, программа не падает.
4. **Безопасная работа с файлом.** Сохранение идёт во временный `.tmp` и затем `os.replace` (атомарная замена). Повреждённый файл не перезаписывается молча: он переименовывается в `*.broken-<дата>`.
5. **Сохранение после каждого изменения**, а не только при выходе - данные не теряются при аварийном закрытии.
6. **Инвентарный номер неизменяем.** `update_item(items, number, /, **changes)` - номер передаётся позиционно (дефект D-01), попытка изменить поле `number` даёт ошибку.
7. **Устойчивость ввода.** `EOFError` (Ctrl+D) превращается во внутреннее `UserQuit` и штатное завершение.

## Ключевые функции
| Функция | Модуль | Назначение |
|---|---|---|
| `normalize_item`, `validate_item` | inventory | очистка и проверка данных |
| `add_item`, `update_item`, `delete_item` | inventory | операции над списком |
| `find_by_number`, `search`, `filter_items` | inventory | поиск и фильтрация |
| `next_number` | inventory | автоматический номер `INV-NNN` |
| `load_items`, `save_items` | storage | чтение/запись JSON |
| `App.run` | main | главный цикл меню |
