# Финальная сводка и план демонстрации

## Требования и результат
Реализованы все 10 User Stories: просмотр, добавление с проверкой, уникальные номера, поиск (номер/кабинет/название), изменение, удаление с подтверждением, фильтры, хранение в JSON, защита от повреждённого файла.

## Реализованные функции
Меню из 6 пунктов; 7 полей карточки (5 обязательных); автоматическая нумерация `INV-NNN`; очистка необязательных полей; атомарное сохранение; 75 автотестов.

## Демонстрация (≈ 7 минут)
1. `python main.py` - показать 12 записей (пункт 1).
2. Пункт 2: добавить оборудование (номер пустой - автоматический); повторить с тем же номером - ошибка.
3. Пункт 3: найти по номеру, по кабинету; неизвестный номер - «Не найдено».
4. Пункт 4: сменить кабинет и состояние.
5. Выйти (0), запустить снова - изменения на месте.
6. Пункт 6: фильтр «требует ремонта».
7. Пункт 5: удалить запись с подтверждением.
8. Показать `python -m pytest` и историю `git log --oneline --graph`.
9. Показать повреждённый JSON: предупреждение и файл `*.broken-*`.

## Структура презентации (5 слайдов)
Проблема заказчика → User Stories → Архитектура (3 слоя) → Тесты и найденные дефекты → Демонстрация и ограничения.

## Ограничения и дальнейшие шаги
Многопользовательской работы нет; номер последней удалённой записи может выдаться повторно (N-5.1); нет истории изменений и импорта из Excel; Dockerfile не проверялся на машине подготовки.
