# Система учёта инвентаря компьютерных классов (итоговая версия, спринт 6)

Консольное приложение на Python для учёта компьютерного оборудования колледжа.
**Проблема заказчика:** в колледже теряется информация об оборудовании - непонятно, где что стоит и в каком оно состоянии.

**Состояние на конец спринта 6 (итог):** все функции плана реализованы: просмотр, добавление, поиск, изменение, удаление, фильтр, хранение в JSON. Подготовлены инструкция пользователя и отчёт о тестировании.

Подробная инструкция: `docs/USER_GUIDE.md`. Хранение: данные в `data/inventory.json`, при повреждении файла копия сохраняется как `*.broken-<дата>`.

## Требования
Python 3.11+ (pytest - только для запуска тестов, `pip install -r requirements.txt`).

## Запуск
```bash
python main.py
```

## Меню
| Пункт | Действие |
|---|---|
| 1 | Показать оборудование (таблица и число записей) |
| 2 | Добавить оборудование: номер (Enter - автоматически), тип, наименование, кабинет, состояние, дата и ответственный (необязательно) |
| 3 | Найти: по номеру (карточка), по кабинету или по названию/типу (таблица) |
| 4 | Изменить запись (Enter - оставить поле без изменений) |
| 5 | Удалить запись (с подтверждением «да/нет») |
| 6 | Фильтр по кабинету и/или состоянию |
| 0 | Выход |

Правила заполнения полей - `docs/DATA_RULES.md`.

## Тесты
```bash
python -m pytest
python -m unittest discover -s tests -t .
```
75 тестов: логика, хранение, меню и перезапуски, фильтр, демо-данные. Отчёт - `docs/TEST_REPORT.md`.

## Структура
```
main.py             меню и ввод/вывод
inventory.py        проверка данных, добавление, поиск, изменение, удаление, фильтр
storage.py          чтение и запись JSON
data/inventory.json файл данных (12 демонстрационных записей)
tests/              автотесты
Dockerfile          образ для запуска (не проверялся)
USER_STORIES.md     требования (все 10 выполнены)
docs/               инструкция, правила данных, тест-кейсы, отчёт о тестировании, дефекты
```

## Ограничения
- Интерфейс только консольный; многопользовательской работы нет: два одновременных запуска могут перезаписать изменения друг друга.
- Инвентарный номер после создания менять нельзя (удалите запись и создайте заново).
- Если удалить последнюю запись, её номер будет выдан следующей новой записи автоматически (известное ограничение N-5.1) - при необходимости задавайте номер вручную.
- Нет истории изменений, импорта из Excel и разграничения прав.
- Один JSON-файл подходит для сотен записей; для тысяч нужна база данных.
- Dockerfile не проверялся на машине подготовки (нет Docker).
