# Система учёта инвентаря компьютерных классов (спринт 2)

Консольное приложение на Python для учёта компьютерного оборудования колледжа.
**Проблема заказчика:** в колледже теряется информация об оборудовании - непонятно, где что стоит и в каком оно состоянии.

**Состояние на конец спринта 2:** можно просматривать оборудование (пункт 1) и добавлять новое с проверкой данных (пункт 2). Поиск, изменение и удаление - спринт 3, хранение в JSON - спринт 4.

> Пока данные хранятся в памяти: после выхода добавленные записи пропадают, при следующем запуске снова загружаются 12 демонстрационных (`data/inventory.json`).

## Требования
Python 3.11+ (pytest - только для запуска тестов).

## Запуск
```bash
python main.py
```

## Меню
| Пункт | Действие |
|---|---|
| 1 | Показать оборудование (таблица и число записей) |
| 2 | Добавить оборудование: номер (Enter - автоматически), тип, наименование, кабинет, состояние, дата и ответственный (необязательно) |
| 3-5 | Поиск, изменение, удаление - появятся в спринте 3 |
| 0 | Выход |

Правила заполнения полей - `docs/DATA_RULES.md`. Ошибки (пустое обязательное поле, повторный номер, неверное состояние или дата) выводятся сообщением, запись не добавляется, программа продолжает работу.

## Тесты
```bash
python -m pytest
python -m unittest discover -s tests -t .
```
26 тестов: логика (`test_inventory.py`), меню (`test_cli.py`), демо-данные (`test_sprint1.py`).

## Структура
```
main.py             меню и ввод/вывод
inventory.py        проверка данных, добавление, автонумерация
data/inventory.json демонстрационные данные (12 записей)
tests/              автотесты
USER_STORIES.md     требования
docs/               правила данных, тест-кейсы, журнал замечаний
```

## Ограничения спринта 2
Нет поиска, изменения, удаления и сохранения в файл; при ошибке в одном поле форму нужно заполнить заново.
