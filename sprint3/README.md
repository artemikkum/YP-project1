# Система учёта инвентаря компьютерных классов (спринт 3)

Консольное приложение на Python для учёта компьютерного оборудования колледжа.
**Проблема заказчика:** в колледже теряется информация об оборудовании - непонятно, где что стоит и в каком оно состоянии.

**Состояние на конец спринта 3:** работают просмотр, добавление, поиск, изменение и удаление записей. Хранение в JSON - спринт 4, фильтр - спринт 5.

> Данные хранятся в памяти: после выхода изменения пропадают.

## Требования
Python 3.11+ (pytest - только для запуска тестов, `pip install -r requirements.txt`).

## Запуск
```bash
python main.py
```

## Меню
| Пункт | Действие |
|---|---|
| 1 | Показать оборудование (таблица и число записей) |
| 2 | Добавить оборудование: номер (Enter - автоматически), тип, наименование, кабинет, состояние, дата и ответственный (необязательно) |
| 3 | Найти: по номеру (карточка), по кабинету или по названию/типу (таблица) |
| 4 | Изменить запись (Enter - оставить поле без изменений) |
| 5 | Удалить запись (с подтверждением «да/нет») |
| 0 | Выход |

Правила заполнения полей - `docs/DATA_RULES.md`.

## Тесты
```bash
python -m pytest
python -m unittest discover -s tests -t .
```
48 тестов: логика (`test_inventory.py`), меню (`test_cli.py`), демо-данные (`test_sprint1.py`).

## Структура
```
main.py             меню и ввод/вывод
inventory.py        проверка данных, добавление, поиск, изменение, удаление
data/inventory.json демонстрационные данные (12 записей)
tests/              автотесты
USER_STORIES.md     требования
docs/               правила данных, чек-лист приёмки, тест-кейсы, дефекты
```

## Ограничения
- Данные пока только в памяти: после выхода изменения пропадают, при запуске снова загружаются 12 демонстрационных записей (сохранение - спринт 4).
- Нет фильтра по состоянию (спринт 5).
- Инвентарный номер после создания менять нельзя.
